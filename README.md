# Circula Library API

A Java 17 / Spring Boot REST API for borrowers, book copies, and active loans.

## Run locally

Requires Java 17 and Maven (or use the included wrapper):

```sh
./mvnw spring-boot:run
```

On Windows, run `mvnw.cmd spring-boot:run`. To run Compose with local settings, copy `.env.example` to `.env`, replace the sample password, and run `docker compose up --build`.

The default profile uses an in-memory H2 database, so data is cleared when the process stops. Set `PORT`, `DB_URL`, `DB_USERNAME`, `DB_PASSWORD`, `DB_DRIVER`, `DDL_AUTO`, and `H2_CONSOLE_ENABLED` to configure the process without changing code. For example, PostgreSQL can be used with `DB_URL=jdbc:postgresql://localhost:5432/circula`, `DB_USERNAME`, `DB_PASSWORD`, and `DB_DRIVER=org.postgresql.Driver`.

## API documentation

After the application starts, open Swagger UI at [http://localhost:8080/swagger-ui/index.html](http://localhost:8080/swagger-ui/index.html). The generated OpenAPI 3 document is available at [http://localhost:8080/v3/api-docs](http://localhost:8080/v3/api-docs). If the server uses a different `PORT`, substitute that port in the URLs.

Swagger UI lets you inspect each endpoint and send requests to the running API. All operations are unauthenticated in this development setup.

Run the API and PostgreSQL using Docker Compose:

```sh
docker compose up --build
```

The Compose setup persists PostgreSQL data in a named volume. Change `POSTGRES_PASSWORD` before exposing the service beyond a local development environment. Schema generation defaults to `update` for local startup; production deployments should apply managed schema migrations and set `DDL_AUTO=validate`.

## Environment configuration

`src/main/resources/application.yaml` contains the default settings. Spring Boot also loads `application-prod.yaml` when `SPRING_PROFILES_ACTIVE=prod`. The production profile disables the H2 console and Swagger/OpenAPI by default, and uses `DDL_AUTO=validate` unless overridden. Supply database settings through environment variables; `.env.example` shows the variables for local Compose or a direct PostgreSQL connection. Environment variable values override the defaults.

## Tests and CI

Run the API tests and package the application with:

```sh
./mvnw --batch-mode verify
```

The tests exercise borrower and book registration, field validation, duplicate email and ISBN metadata conflicts, book listing and availability, borrow/return flows, and not-found/conflict responses. GitHub Actions runs the same Maven verification and builds the Docker image for pushes and pull requests.

## Kubernetes

The manifests in `k8s/` create a PostgreSQL StatefulSet with persistent storage and the Circula API Deployment and Service. For a local cluster, first build and load the image (the exact load command depends on the cluster):

```sh
docker build -t circula:latest .
kubectl create secret generic circula-db-secret --from-literal=password='replace-with-a-strong-password'
kubectl apply -f k8s/configmap.yaml
kubectl apply -f k8s/deployment.yaml
kubectl port-forward service/circula-api 8080:8080
```

The API is then available at `http://localhost:8080`; the Kubernetes demo ConfigMap enables Swagger UI at `http://localhost:8080/swagger-ui/index.html`. The `prod` profile disables Swagger by default, so set `OPENAPI_ENABLED=true` only when you intend to expose it. In Minikube, load the image with `minikube image load circula:latest`; for a remote cluster, publish the image and set `k8s/deployment.yaml` to its registry name. The Kubernetes ConfigMap uses `DDL_AUTO=update` so a fresh demo install starts without a migration step. Before production use, apply versioned schema migrations and change the value to `validate`.

## API

All endpoints are under `/api`. Request and response bodies use JSON. IDs are generated by the server. `409 Conflict` indicates duplicate borrower email, ISBN metadata disagreement, or an already-borrowed copy. `404 Not Found` indicates an unknown resource or no active matching loan. Validation failures return `400` with field details.

### Register a borrower

`POST /api/borrowers`

Example request payload: [`src/main/resources/static/examples/borrower.json`](src/main/resources/static/examples/borrower.json). Swagger UI uses this same file as its request example.

```json
{"name":"Ada Lovelace","email":"ada@example.com"}
```

Returns `201 Created` and `{ "id": 1, "name": "Ada Lovelace", "email": "ada@example.com" }`. Email addresses are unique, case-insensitively.

### Register a book copy

`POST /api/books`

Example request payload: [`src/main/resources/static/examples/book.json`](src/main/resources/static/examples/book.json). Swagger UI uses this same file as its request example.

```json
{"isbn":"9780132350884","title":"Clean Code","author":"Robert C. Martin"}
```

Each request creates a distinct copy with its own ID, including when ISBN, title, and author match an existing copy. An ISBN already in the catalog cannot be registered with a different title or author.

Returns `201 Created` with `{ "id": 1, "isbn": "9780132350884", "title": "Clean Code", "author": "Robert C. Martin", "available": true }`.

### List books

`GET /api/books` returns every registered copy, each with `id`, `isbn`, `title`, `author`, and `available`.

Returns `200 OK` with a JSON array; an empty catalog returns `[]`.

### Borrow a copy

`POST /api/borrowers/{borrowerId}/books/{bookId}/borrow`

Loan creation has no JSON request body. Use the borrower and book copy IDs returned by their registration endpoints in the URL, for example `POST /api/borrowers/1/books/1/borrow`. Swagger UI shows `1` as an example for both path parameters.

Returns `201 Created` with loan ID and timestamps. A book ID identifies one copy, and an active loan prevents any other borrower from borrowing that copy. Separate copies sharing an ISBN can be borrowed independently.

The response contains `id`, `bookId`, `borrowerId`, `borrowedAt`, and `returnedAt` (`null` while the loan is active).

### Return a copy

`POST /api/borrowers/{borrowerId}/books/{bookId}/return`

Returns the loan record with `returnedAt` set. Only the borrower with the active loan can return that copy.

Returns `200 OK` with the same loan fields and a populated `returnedAt` timestamp.

### Errors and validation

- `400 Bad Request`: request fields are invalid. The response includes an `error` and a `fields` object keyed by field name. Borrower names are limited to 120 characters, emails must be valid and at most 254 characters, ISBNs are limited to 32 characters, titles to 250, and authors to 160. Required strings cannot be blank.
- `404 Not Found`: borrower or book ID is unknown, or there is no active loan matching the borrower and book IDs.
- `409 Conflict`: borrower email already exists, ISBN metadata conflicts with the catalog, or the physical copy is already on loan.

Error response example:

```json
{"status":400,"error":"Validation failed","fields":{"email":"must be a well-formed email address"}}
```

Example:

```sh
curl -X POST http://localhost:8080/api/borrowers \
  -H 'Content-Type: application/json' \
  -d '{"name":"Ada Lovelace","email":"ada@example.com"}'
```

## Data and assumptions

- PostgreSQL is the recommended shared database: it provides durable relational storage, foreign keys, and transaction/row-lock support for concurrent borrow requests. H2 is provided for convenient local development and a zero-setup run.
- `Book` represents one physical copy. ISBN is intentionally indexed but not unique; copies sharing an ISBN share identical title and author metadata.
- Borrower email is treated as a unique identifier for registration, normalized to lowercase. The task requires a borrower email but does not specify duplicate handling.
- ISBN is required and length-limited but not checked for ISBN-10/ISBN-13 checksum or canonical formatting; the task does not specify validation rules.
- A borrower may have multiple simultaneous loans, including multiple copies of the same title. No due date, fines, authentication, pagination, or loan history endpoint is specified.
- A return is accepted only for an active loan belonging to the borrower in the URL; repeating a return returns `404`.
- There is no delete endpoint. `available` is derived from whether the copy has an active loan.
- Schema generation defaults to `update` for easy startup. Production should use a migration tool and validate the schema instead.
